## Q10: B / A database UNIQUE constraint on the email column

A UNIQUE constraint makes the database enforce uniqueness across concurrent writes. An application-level check alone has a check-then-act race. The application must still handle the rejected insert; case folding and email normalization are separate design decisions.

[Source](https://www.postgresql.org/docs/current/ddl-constraints.html#DDL-CONSTRAINTS-UNIQUE-CONSTRAINTS)

## A / Atomically record a unique event ID and apply the effect in the same transaction, skipping IDs already recorded

A database-enforced unique event ID and the effect in one transaction prevent duplicate application while keeping the marker and effect consistent. Acknowledge after commit and retain deduplication records for the relevant replay window. External payment APIs need their own idempotency strategy; this answer only covers the stated database-local effect.

[Source](https://microservices.io/post/microservices/patterns/2020/10/16/idempotent-consumer.html)
