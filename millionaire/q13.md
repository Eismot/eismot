## Q12: D / Linearizable consistency and availability for every request to a non-failing node

CAP's consistency is linearizability, not the C in ACID. Its availability requires every request to a non-failing node to eventually complete with a valid response. Under a partition, a system cannot guarantee both. This is not a general instruction to pick any two letters regardless of network conditions.

[Source](https://www.cs.princeton.edu/courses/archive/spr22/cos418/papers/cap.pdf)

## B / There is a data race, so the behavior is undefined

Conflicting non-atomic accesses in different threads without a happens-before ordering cause a data race and undefined behavior. volatile is not a thread-synchronization mechanism. Use suitable atomics or locking; visibility of a single value is not the only concern.

[Source](https://en.cppreference.com/w/cpp/language/multithread.html)
