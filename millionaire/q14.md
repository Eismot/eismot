## Q13: B / There is a data race, so the behavior is undefined

Conflicting non-atomic accesses in different threads without a happens-before ordering cause a data race and undefined behavior. volatile is not a thread-synchronization mechanism. Use suitable atomics or locking; visibility of a single value is not the only concern.

[Source](https://en.cppreference.com/w/cpp/language/multithread.html)

## C / All edge weights are non-negative

Non-negative edge weights support Dijkstra's greedy finalization argument; zero-weight edges are allowed. Negative edges can break that argument even without cycles. A DAG can instead use a topological-order shortest-path algorithm that allows negative weights.

[Source](https://www.boost.org/doc/libs/release/libs/graph/doc/dijkstra_shortest_paths.html)
