## Q11: A / Atomically record a unique event ID and apply the effect in the same transaction, skipping IDs already recorded

A database-enforced unique event ID and the effect in one transaction prevent duplicate application while keeping the marker and effect consistent. Acknowledge after commit and retain deduplication records for the relevant replay window. External payment APIs need their own idempotency strategy; this answer only covers the stated database-local effect.

[Source](https://microservices.io/post/microservices/patterns/2020/10/16/idempotent-consumer.html)

## D / Linearizable consistency and availability for every request to a non-failing node

CAP's consistency is linearizability, not the C in ACID. Its availability requires every request to a non-failing node to eventually complete with a valid response. Under a partition, a system cannot guarantee both. This is not a general instruction to pick any two letters regardless of network conditions.

[Source](https://www.cs.princeton.edu/courses/archive/spr22/cos418/papers/cap.pdf)
